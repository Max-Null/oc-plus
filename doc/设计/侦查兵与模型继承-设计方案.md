# 侦查兵（Scout）与子 Agent 模型继承——设计方案

> 状态：待评审 | 日期：2026-08-08 | 关联：oc-plus 部署体系（deploy.mjs V3.11）

## 1. 背景与目标

### 1.1 背景

1. **DeepSeek V4-Flash 正式版已发布**（2026-07-31），能力超过 V4-Pro 预览版；V4-Pro 正式版预计 2026-08 月初发布。当前子 agent 的 `DS_MODEL_HIGH` 仍硬编码为 pro，与"先全 flash、等 pro 正式版恢复高低配"的策略不符。
2. **DeepSeek 提供原生服务端联网搜索**：Responses API（`/responses`）与 Anthropic 兼容端点（`/anthropic`）均支持 `web_search` 内置工具，服务端执行，无需第三方搜索服务。
3. opencode 当前联网能力依赖 Exa websearch MCP（function 工具路径），未使用服务端搜索。

### 1.2 目标

- **模型动态化**：子 agent（参谋/军师）模型跟随主 agent（双星）运行时切换，TUI/桌面端一键切换即生效，不再依赖静态别名配置。
- **服务端搜索**：新增"侦查兵"子 agent，专职联网调研，优先使用 DeepSeek 服务端 web_search，Exa 兜底。
- **成本可控**：侦查兵固定 flash；工匠保持 LOW（flash）固定。

### 1.3 非目标

- 不改造参谋/军师的协议（跟随双星模型，无法固定 Anthropic 协议；pro 暂不支持）。
- 不写 opencode 插件（配置层可解决，不引入维护负担）。
- 不处理 V4-Pro 正式版发布后的回归（届时仅需 TUI 切换，无需改配置）。

## 2. 现状与验证

### 2.1 模型部署链路

```
双星系统/agents/*.md（源：model: "DS_MODEL_HIGH" 等占位符）
        │  deploy.mjs patchAgentModel（读 model-aliases.json 替换）
        ▼
model-aliases.json（DS_MODEL_LOW→flash / DS_MODEL_HIGH→pro / DS_MODEL_VISION→kimi-k3）
        │
        ▼
~/.config/opencode/agents/*.md（部署产物，无条件覆盖，手动修改无效）
```

### 2.2 关键机制确认

**opencode 子 agent 模型继承**（V2 docs/agents + PR #4894）：

> "A child session uses its subagent's configured model, or **inherits the parent session's model** when none is configured."

即：子 agent 不写 `model` 字段 → 派发时继承主 agent 当前会话模型（TUI/桌面端切换立即生效）。

### 2.3 端点实测（2026-08-08，curl 验证）

| 端点 | 请求格式 | 结果 |
|------|---------|------|
| `POST https://api.deepseek.com/responses` | `tools:[{"type":"web_search"}]` + `tool_choice` | ✅ 200，返回 `web_search_call`，搜索真实执行 |
| `POST https://api.deepseek.com/anthropic/v1/messages` | `tools:[{"type":"web_search_20260209","name":"web_search"}]` | ✅ 200，`server_tool_use` → `web_search_tool_result` |
| `POST https://api.deepseek.com/anthropic/v1/messages` | `tools:[{"name":"get_weather","input_schema":{...}}]`（function） | ✅ 200，标准 `tool_use` + `stop_reason: "tool_use"`，`cache_read_input_tokens: 256`（缓存正常） |

**注意**：Anthropic 端点不接受 `server_tool_use` 类型声明（400），必须用 Anthropic 原生格式 `web_search_20250305` / `web_search_20260209`。此结论修正了 opencode issue #32273 中"server_tool_use"的说法。

**兼容性要点**（Responses API 官方文档）：
- 仅 `deepseek-v4-flash` 支持；pro 预计 2026-08 初
- `tool_choice` 可强制 `{"type":"web_search"}`（tools 中必须存在，否则 400）
- 无状态 API；不支持的参数静默忽略

## 3. 方案设计

### 3.1 模型继承机制改造（参谋/军师动态化）

**改动文件**（oc-plus 源，非部署产物）：

| 文件 | 改动 | 效果 |
|------|------|------|
| `双星系统/agents/参谋.md` | 删除 `model: "DS_MODEL_HIGH"` 行；permission 增加 `task: {"侦查兵": "allow"}` | 派发时继承双星当前模型；可调用侦查兵（仅此一个） |
| `双星系统/agents/军师.md` | 删除 `model: "DS_MODEL_HIGH"` 行；permission 增加 `task: {"侦查兵": "allow"}` | 同上 |
| `双星系统/agents/双星.md` | 保留 `model: "DS_MODEL_HIGH"` | 主 agent 默认值（新会话），切换后失效 |
| `双星系统/agents/工匠.md` | `model` 改为 `"ds-anthropic/deepseek-v4-flash"`（Anthropic 协议）；保留 `task deny` | 固定 flash + **自主服务端搜索**（function 工具实测正常）；"不委派"铁律不受影响 |
| `双星系统/agents/制图师.md` | 保留 `model: "DS_MODEL_VISION"` | Kimi K3 多模态不可替代 |
| `model-aliases.json` | 保留（DS_MODEL_HIGH 暂时无引用） | 等 pro 正式版可改回/删除 |
| 根级 `opencode.json` | 增加 `subagent_depth: 2` | 允许 subagent 再派发一层（配合逐 agent 的 task 授权） |

**调用链**：双星 → 参谋/军师（仅可派发侦查兵）→ 侦查兵（task deny，链路终止）。工匠保持零派发。

**deploy.mjs 兼容性**：`patchAgentModel` 对无 model 行文件安全（正则不匹配 → 原样保留）。无需改 deploy.mjs。

### 3.2 新增 Provider：`ds-anthropic`（服务端搜索通道）

```jsonc
// ~/.config/opencode/opencode.json（或 oc-plus 部署时合并）
"ds-anthropic": {
  "npm": "@ai-sdk/anthropic",
  "options": { "baseURL": "https://api.deepseek.com/anthropic" },
  "models": {
    "deepseek-v4-flash": {
      "name": "DeepSeek V4 Flash（服务端搜索）",
      "limit": { "context": 1000000, "output": 131072 }
    }
  }
}
```

- 不动现有 `ds` provider（Chat Completions 路径保持稳定）
- **写入位置**：`~/.config/opencode/opencode.json`（deploy.mjs 不管理 opencode.json，需手动合并；oc-plus 项目根 opencode.json 只是模板）
- Anthropic 协议层由 opencode 原生支持 `web_search` provider 工具（若自动注入）；未注入时侦查兵退回 Exa

### 3.3 新增 Agent：`侦查兵`

```markdown
---
description: 联网调研 — 专职搜索/查资料，只读不写
mode: all
model: "ds-anthropic/deepseek-v4-flash"   # 固定 flash（决策：成本可控）
temperature: 0.2
permission:
  read: allow
  glob: allow
  grep: allow
  webfetch: allow
  websearch: allow
  edit: deny
  write: deny
  bash: deny
  task: "*": deny
---
```

**prompt 核心**（调研工作流）：
1. 收到调研主题 → 拆解 2-3 组精准关键词 → 优先服务端 web_search（Anthropic 协议自动注入时），否则用 websearch（Exa）
2. 多轮搜索交叉验证 → 抓取原始页面（webfetch）核实关键事实
3. 返回：调研结论（要点 + 来源链接），禁止输出无来源支持的事实
4. 无可靠来源时明确说明"未找到"，禁止编造

**权限边界**：只读 + 搜索。无编辑、无 shell、无子 agent 派发（`task: "*": deny`）。

**可调用者**：双星（主 agent）、参谋、军师（后两者通过 `task: {"侦查兵": "allow"}` 精确授权）。侦查兵自身不可再派发。

### 3.4 数据流

```
主 agent（双星）──task 派发 / 用户 @侦查兵──▶ 侦查兵（flash + Anthropic 协议）
                                                 │
                                    服务端 web_search（优先）/ Exa websearch + webfetch（兜底）
                                                 │
                             返回调研结论（要点 + 来源链接），不污染主上下文
```

## 4. 验证计划（门控结构）

**核心原则**：验证 2/3 是**门控项**——未通过则砍掉 ds-anthropic 相关改动（侦查兵退回 Exa），方案体积减半。

| # | 验证项 | 门控 | 方法 | 预期 |
|---|--------|------|------|------|
| 1 | 端点 web_search 可用性 | — | ✅ 已完成（2.3 节） | 200 + 真实搜索结果 |
| 2 | opencode 注入 web_search 工具声明 | **GATE** | 部署后派发侦查兵任务，观察请求体 | 请求含 `web_search_20260209` 工具 |
| 3 | 侦查兵搜索真实执行 | **GATE** | 派发"今天科技新闻"类任务 | 返回含 2026-08 时效性信息 + 来源 |
| 4 | 模型继承生效 | Phase 1 | 双星会话切 flash → 派参谋，观察消耗模型 | 参谋走 flash |
| 5 | 参谋/军师可派发侦查兵 | Phase 1 | 参谋任务中触发 task(侦查兵) | 授权生效，工匠仍无法派发 |
| 6 | 兜底路径 | 任何阶段 | 若验证 2/3 失败，侦查兵自动用 Exa | 任务仍成功 |

**决策分支**：
- GATE 通过 → 全量实施（参谋/军师授权、subagent_depth、工匠切换[可选]）
- GATE 失败 → 移除 ds-anthropic provider，侦查兵固定 `ds/deepseek-v4-flash` + Exa；模型继承照常实施

### 验证结果（2026-08-08 实测回填）

| # | 结果 | 实测说明 |
|---|------|---------|
| 1 | ✅ | 端点 `POST /anthropic/v1/messages` 返回 200 + 真实搜索结果（2.3 节，前期完成） |
| 2 | ❌ | 部署后派发侦查兵，请求体**未注入** `web_search_20260209` 工具声明——opencode 1.18.15 未自动注入服务端搜索工具 |
| 3 | ❌ | 因 #2 未注入，服务端搜索未真实执行（未产生 web_search 请求） |
| 4 | ✅ | 部署产物参谋.md/军师.md 均无 model 行（配置层继承确认）；参谋自报运行模型 `ds/deepseek-v4-flash` 与双星当前模型一致（静态观察，未做双模型切换对照） |
| 5 | ✅ | 参谋任务中派发 `task(侦查兵)` 未触发权限拦截，侦查兵正常返回调研结果 |
| 6 | ✅ | 回退后实测：侦查兵 websearch（Exa）8 次 7 成功 + webfetch 3 次成功，返回 2026-08 时效性科技新闻（OpenAI Astra、谷歌 AI 重组、SK Hynix 380 亿投资等）+ 多源交叉验证 + 来源链接；1 次搜索短暂故障重试恢复 |

**GATE 决策（已执行）**：验证 #2/#3 失败 → 按失败分支回滚：移除 `~/.config/opencode/opencode.json` 的 `ds-anthropic` provider、侦查兵 model 固定 `DS_MODEL_LOW`（`ds/deepseek-v4-flash`）+ Exa、`model-aliases.json` 不保留 `DS_MODEL_ANTHROPIC`。模型继承（#4/#5）与兜底路径（#6）照常实施并通过。侦查兵即日投入使用。

## 5. 风险与回滚

| 风险 | 影响 | 缓解 |
|------|------|------|
| opencode 1.18.15 未自动注入 web_search | 侦查兵退回 Exa（功能不降级） | 兜底路径已设计；不写插件 |
| 主 agent 切到 Kimi K3 | 参谋/军师跟随 K3（视觉模型） | 用户切换时自知；可接受 |
| Anthropic 协议 thinking 行为差异 | 仅影响侦查兵（调研场景，可接受） | 不涉及工匠/主 agent |
| pro 正式版发布 | 需 TUI 切换恢复高低配 | 无需改配置 |

**回滚**：deploy.mjs 自带备份（`~/.config/opencode/.deploy-backup`）+ `回滚.bat`；恢复 agent model 行或 git revert 即可。

## 6. 实施步骤（两阶段门控）

**Phase 0（最小改动，验证门控）**：
1. `model-aliases.json` 新增 `DS_MODEL_ANTHROPIC`
2. 新建 `双星系统/agents/侦查兵.md`（model 引用别名）
3. `deploy.mjs` agentFiles 显式列表新增侦查兵条目（第 517-524 行）
4. 手动合并 `ds-anthropic` provider 到 `~/.config/opencode/opencode.json`（subagent_depth 暂不加）
5. `node deploy.mjs` 部署 + 备份
6. 验证 GATE 项（#2 注入、#3 真实执行）
7. GATE 通过 → 进入 Phase 1；失败 → 移除 ds-anthropic，侦查兵改 `ds/deepseek-v4-flash` + Exa，方案收窄

**Phase 1（GATE 通过后）**：
8. 参谋/军师源文件：删 model 行 + `task: {"侦查兵": "allow"}`
9. `~/.config/opencode/opencode.json` 加 `subagent_depth: 2`
10. 部署 + 验证 #4 继承、#5 派发
11. （可选）工匠 model 改 `DS_MODEL_ANTHROPIC`——收益边际（已有 context7 覆盖文档查询），行为变化风险相对最大，由用户决定
12. 更新 doc/设计/README.md 索引 + git 提交（分阶段提交，每阶段自闭环）

## 7. 纠偏记录（2026-08-08 专业复审）

| 原设计 | 纠偏结论 | 依据 |
|--------|---------|------|
| 6 任务全量实施，验证放最后 | **验证门控两阶段**：Phase 0 最小改动先证伪关键假设（web_search 注入），结果决定 Phase 1 投入 | 关键假设未验证前全量投入是最大风险；用 30% 改动验证 70% 风险 |
| "增加搜索能力"是核心需求 | **搜索能力已是伪需求**：websearch/webfetch 默认对所有 agent 可用。真正增量只有服务端搜索 + 侦查兵职责封装 | 现状盘点：所有 agent 已有 Exa 搜索 |
| 工匠切 Anthropic 协议（必做） | **降级为可选**：收益边际（context7 已覆盖文档查询），行为变化风险相对最大 | 收益/风险比不划算 |
| —（新增） | **可选增强：调研沉淀闭环**——侦查兵结论由双星判断后写入分形记忆块（pending），调研从一次性问答变知识沉淀入口 | 让功能对 DS 有长期价值 |

## 8. 决策记录

| 决策 | 理由 |
|------|------|
| 验证门控两阶段实施 | 关键假设（opencode 注入 web_search）未验证前不全量投入；GATE 失败则方案收窄减半 |
| 侦查兵固定 flash | 搜索不需要高推理，成本可控 |
| 参谋/军师继承主模型 | 动态高低配，TUI 一键切换，无配置维护 |
| 参谋/军师可调用侦查兵 | 职责分离：判断者（参谋/军师）与信息采集者（侦查兵）各司其职，避免重复搜索；精确授权（仅侦查兵）不放开其他派发 |
| 工匠切换降级为可选 | context7 已覆盖文档查询，服务端搜索是边际收益；编码行为稳定性优先 |
| 用 Anthropic 协议而非 Responses API | opencode 对 Anthropic 协议原生支持 web_search；Responses API 需 @ai-sdk/openai 且无注入开关 |
| 不写插件 | 配置层可解决，避免 opencode 内部 API 依赖 |
